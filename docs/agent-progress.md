- **Local discovery implementation (PR #6 + PR #19):**
  - `LocalCameraNsd` advertises `_lanmonitor._tcp.` with stable Camera UUID and protocol version in DNS-SD TXT data; no temporary pairing token is broadcast.
  - Monitor can search all Lan Monitor service advertisements before pairing, or restrict discovery to the stable UUID imported from a QR. Resolved service records must have the supported protocol version, canonical UUID and a private IPv4 endpoint.
  - Selecting a discovered Camera starts an open-LAN join without QR/token; QR scanning and manual IP/token entry remain optional paired-flow alternatives.
  - NSD is optional. If unavailable or registration/discovery fails, the app shows an explanatory status and leaves manual pairing/address entry available.
  - A Wi-Fi multicast lock is acquired only for Android 13 devices without T extension 7, and released on discovery stop/failure.
  - `CameraDiscoveryPolicy` is pure Kotlin with tests for matching identity, malformed IDs, missing endpoints, and private/public address handling.
- **Active-session recovery (PR #7, merged; multi-Monitor isolation in PR #20):** Each Monitor retains its latest Camera endpoint, retries signaling with bounded exponential backoff, and rebuilds only its own WebRTC peer after ICE failure or a 10-second frame stall. Paired mode also retains the current session token and stops retrying after an explicitly rejected token. Physical Wi-Fi/IP-change and two-Monitor recovery remain `NOT TESTED`; signaling is unencrypted `ws://` on a trusted home LAN.
- **Foreground-service scaffolding (PR #8, merged):** Camera uses `camera|microphone`; Monitor uses `mediaPlayback`. Both have an ongoing Stop notification, contextual notification permission handling and task-removal cleanup. Post-merge CI passed; physical background/screen-off behavior remains `NOT TESTED`.
- **Session-controller retention (PR #9, merged):** `SessionControllerStore` shares role-specific controllers between Compose and the foreground service; UI detach releases only the screen lease/renderer, while the service retains the active controller. Explicit Back and notification Stop terminate the session; one active role is enforced. This supports in-process Activity recreation only, not process-death recovery. Deterministic retention-policy tests are added.
- **Camera startup cleanup (PR #10, merged):** `startLocalMedia()` acquires the camera capturer, texture helper, video/audio sources and tracks transactionally. If initialization fails before ownership transfers to the session, it attempts to stop capture and disposes every resource created so far. The post-merge Android Development Release succeeded.
